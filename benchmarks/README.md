# Benchmark evidence (Phase 3B)

Everything here was produced by the tooling in `scripts/bench/` and `load-tests/k6/` (see
`docs/14-deployment-guide.md` §5d). Nothing is edited by hand.

| Path | Contents |
|---|---|
| `results/<UTC time>-<scenario>-<algorithm>-<rps>[-profile][-variant][-target]-r<n>/` | One directory per run: **212 runs, 153 valid and 59 invalid**. Invalid runs are kept with their reasons and are never used in result tables |
| `results/MANIFEST.sha256` | SHA-256 of every file in every run directory, including the raw files that are not in git |
| `reports/phase-3b-final/` | `report.md` / `report.json` generated by `scripts/bench/report.py` from `results/`; `analysis.md` (analysis, optimisation decisions, acceptance checklist); `build_docs11.py` (rebuilds `docs/11-performance-benchmarks.md` from `report.md`) |
| `reports/validation/` | Report from the tooling-validation runs |
| `campaigns/` | Campaign driver logs (`progress.jsonl` per campaign, console logs, queue scripts) |
| `investigations/cold-start/` | The cold-start investigation script and its measurements (`docs/13-failure-handling.md`) |
| `dry-runs/`, `warmups/` | Dry runs (no request sent) and JIT warm-ups; not results |
| `smoke/` | Smoke-test reports (git-ignored, local only) |

## What each run directory holds

| File | In git | Purpose |
|---|---|---|
| `run-meta.json`, `run-steps.json` | yes | Configuration, timings, Redis safety and reset records, faults injected |
| `validity.json`, `reconcile.json`, `correctness.json` | yes | Validity verdict with reasons; count reconciliation; correctness bounds (B5, B6, B10) |
| `sources.json`, `k6-summary.json`, `k6-config.json`, `k6.log` | yes | The counts and k6 results the reports use |
| `k6/` | yes | The exact k6 script, library, environment and `k6 inspect` output used for the run |
| `prometheus/window-summary.json`, `prometheus/ramp-steps.json` | yes | Measurement-window query results |
| `redis/`, `nginx-summary.json`, `nginx/per-user.json`, `docker-stats-summary.json`, `logs/`, `environment.txt` | yes | Redis INFO, latency stats and SLOWLOG; access-log summary; per-user counts (B5, B10); resource summary; container logs (F runs); environment |
| `docker-stats.csv`, `docker-stats.jsonl(.gz)` | no (local) | 1-second container samples |
| `raw-counters/` | no (local) | Raw `/actuator/prometheus` snapshots per instance |
| `prometheus/queries.json` | no (local) | Every Prometheus query and its raw answer |
| `nginx/access-run.log.gz` | no (local) | Raw access-log lines of the run (B10, F1–F5) |

The raw files are kept on the machine that ran the campaign and are covered by `MANIFEST.sha256`; they can be
attached to a release as an archive. They were not deleted or modified.

**Environment:** one Apple M4 laptop (10 cores, 16 GB) running Docker Desktop. All services and the load generator
share it, so results are relative and machine-specific, not production capacity.
